# 80 · ISO-GEN and Modify

Frozen Lamport-20 engine is **not rewritten**. New work is a new run id. Generation is demand-driven, never decorative. Specification exists before the item.

## CANDIDATE lifecycle

1. Teacher states an idea (ordinary language — not a hinge code).
2. T-UNIT maps to a hinge pack (chemistry) or syllabus chapter (phy/bio interim).
3. Teacher confirms the spec.
4. T-AUTHOR authors one MCQ. Stamp: `serve_eligible: false`, `owner_ratified: false`, spec hash, utc. Status CANDIDATE.
5. Tray is local. Nothing enters the live exam pool.
6. Promotion is a **human** protocol. The agent cannot execute it. `owner_ratified` has no agent-writable path.

Phy/bio packet carries explicit `mx: []`. Do not invent a mix-up ledger. Distractors are realizable wrong outputs from the chapter, not “student is confused”.

Do not print SMILES, hinge ids, or node codes in the stem or options. No examiner comments. TikZ is null unless the item needs a simple figure; never nest `circuitikz`.

## Modify (test maker)

ISO-GEN on an **existing** item (P-ITEM-MODIFY-WHOLE). Packet and gates: `83_MODIFY.md` and `harness/modify/`. The kernel compiles `modify_packet.v1` (hinge row, seeds, LBS recipe when bound) then one AI call designs the new item. Formats are not collapsed to four-option MCQ. TikZ only if the spec requires it. Session-only. Revert = packed bytes. Credit-excluded. Key flagged UNVERIFIED.

## Honesty

Olympiad / JEE / MathNet / Phy-500 generation stays bannered until those banks have stems and structured options on TTwin. Until then: curated existing items only, or dark.

ISO-GEN CANDIDATEs cannot evidence transfer (I18).
